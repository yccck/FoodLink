## 一、5 分钟跑通本地联调

### 1. 启动后端（FastAPI，端口 8080）

```bash
cd backend

# 首次：安装依赖（网络慢时加 -i https://mirrors.aliyun.com/pypi/simple/）
pip install -r requirements.txt

# 首次或想重置数据时：建库 + 写入演示账号/演示商品
python scripts/seed_demo.py        # 如提示 No module named 'app'，先执行：set PYTHONPATH=%CD%（Windows）或 export PYTHONPATH=$PWD（Mac/Linux）

# 启动服务
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

验证：浏览器打开 http://localhost:8080/api/health 返回 `{"code":0,...}` 即成功。
接口文档（Swagger）：http://localhost:8080/doc.html

演示账号（密码均 `123456`）：

| 角色 | 账号 | 说明 |
|---|---|---|
| 学生 | `2021001` | 已填偏好/禁忌/月预算，可直接测推荐 |
| 商家 | `shop001` | **已审核通过**，可直接发布商品 |
| 超管 | `admin` | 可进超管后台接口 |

### 2. 启动前端（Vue3 + Vite，端口 5173）

```bash
cd frontend
npm install        # 首次
npm run dev
```

前端开发服务器已配置代理：`/api` 请求会转发到 `http://localhost:8080`（见 `frontend/vite.config.js`），所以**只要后端跑在 8080，前端开箱即用，不用改任何代码**。

### 3. 从 mock 切换到真实后端

前端默认可能走 `mock/vite-mock.js`。切换方式：

- 在 `frontend/.env.development` 中确认 `VITE_API_BASE=/api`（走 vite 代理到 8080）；
- 关闭 mock：将 `vite.config.js` 里 mock 插件注释掉，或设环境变量 `VITE_USE_MOCK=false`（以前端实际实现为准）。

## 二、前端对接后端的 10 条硬约定（改代码前必读）

1. **统一响应**：所有接口返回 `{code, message, data}`。`code=0` 成功；业务失败时 HTTP 多为 200，靠 `code` 判断（如 20001）。
2. **鉴权**：请求头 `Authorization: Bearer <token>`。**HTTP 401 = 未登录/Token 失效**，前端应清空本地 token 并跳登录页（`src/api/request.js` 的响应拦截器已处理）。
3. **登录**：`POST /api/auth/login`，入参 `{login_name, password, role}`（role：1 学生 / 2 商家 / 3 超管）。返回 `data = {token, user:{...}}`，**user 是完整对象**（含 `audit_status`，非商家为 -1）。
4. **登录失败业务码**（HTTP 200，按 code 提示文案）：
   - `20001` 账号或密码错误（含角色选错）
   - `20002` 账号被禁用
   - `20003` 商家未审核（待审核/已驳回，商家端登录页要拦截这个状态）
5. **注册**：学生返回 `{id}`；商家返回 `{id, audit_status:0}`，注册后**不能立即登录**，需超管审核通过。
6. **金额是字符串**：如 `"12.00"`、`"1500.00"`（Decimal 传输防浮点误差）。前端展示直接用，计算时 `Number()` 转换。
7. **时间是字符串**：`yyyy-MM-dd HH:mm:ss`。
8. **收藏**：`POST /api/products/{id}/favorite`，**必须带 body** `{"favorite": true|false}`，返回 `{favorite, fav_count}`——不是无 body 的 toggle。
9. **商品风控**：商家发布商品被拦截时返回 `41001`（敏感词）/ `41002`（价格异常）/ `41003`（有效期异常），前端发布页应toast `message` 提示商家修改。
10. **商品详情**：`GET /api/products/{id}` 携带 token 时返回 `is_favorite`、`merchant.shop_name`、`view_count` 会自动 +1（勿重复调用刷详情）。

## 四、排错速查

| 现象 | 原因 | 解决 |
|---|---|---|
| 前端请求 404 | 后端没启动 / 端口不是 8080 | 确认 `uvicorn ... --port 8080` |
| 一直跳登录页 | token 过期（120 分钟）或后端重启换了密钥 | 重新登录 |
| 商家登录提示「审核中」 | 该商家 `audit_status=0` | 用 admin 调 `PUT /api/admin/merchants/{id}/audit` 通过 |
| 登录报 20001 但账号密码对 | 数据库是旧的，密码字段还是占位符 | 删 `backend/data/foodlink.db` 后重跑 `seed_demo.py` |
| CORS 报错 | 前端不在 5173 端口 | 后端 `.env` 设 `FOODLINK_CORS_ORIGINS` 加上你的前端源 |
| 推荐/猜你喜欢返回空 | 没有在售商品或用户无行为数据 | 先用 shop001 发几个商品；猜你喜欢冷启动会回退热门商品 |
