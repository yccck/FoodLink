# FoodLink 商家模块测评流程

> 测试入口：http://localhost:8080/doc.html
> 前置条件：后端已启动（`uvicorn app.main:app --port 8080`），数据库已跑过 `scripts/seed_demo.py`
> 演示账号：超管 `admin` / 商家 `shop001`（已审核）/ 学生 `2021001`，密码均 `123456`

整个流程模拟一个商家从 **注册 → 审核 → 经营 → 违规被风控 → 被处理** 的完整生命周期，共 5 个阶段、16 个测试点。

---

## 阶段一：商家注册与审核闭环

### 1.1 注册一个新商家

`POST /api/auth/register`

```json
{
  "role": 2,
  "login_name": "testshop01",
  "password": "123456",
  "shop_name": "测试奶茶店",
  "license_img": "",
  "location": "学生街 12 号",
  "lat": "30.520",
  "lng": "120.135",
  "phone": "13900001111"
}
```

**预期**：`code: 0`，`data = {"id": x, "audit_status": 0}`（0 = 待审核）

### 1.2 未审核商家尝试登录（应被拒绝）

`POST /api/auth/login`

```json
{"login_name": "testshop01", "password": "123456", "role": 2}
```

**预期**：`code: 20003`，提示商家未审核 / 审核中——**拿不到 token**

### 1.3 超管查看待审核列表

先登录 `admin`（role=3），复制 token → 点页面右上 **Authorize** 填 `Bearer <token>`。

`GET /api/admin/merchants/pending`

**预期**：`code: 0`，列表里能看到「测试奶茶店」，记下它的 **`id`**（注意：这是 merchant_id，不是 user_id）

### 1.4 超管审核通过

`PUT /api/admin/merchants/{merchant_id}/audit`

```json
{"audit_status": 1}
```

（`1` 通过，`2` 驳回）

**预期**：`code: 0`，`message: "审核通过"`

### 1.5 商家重新登录

重复 1.2 的登录请求。

**预期**：`code: 0`，成功返回 `token` + `user`（`user.audit_status = 1`）。
**把 Authorize 里的 token 换成这个商家 token**，后续阶段二、三都用它。

> ✅ 阶段一验证点：注册 → 未审核拦截（20003）→ 审核 → 可登录，闭环成立。

---

## 阶段二：商家正常经营

### 2.1 发布一个正常商品

`POST /api/products`

```json
{
  "title": "招牌奶茶 买一送一",
  "description": "今日现做，临期特价",
  "category": "饮品",
  "original_price": "15.00",
  "discount_price": "7.50",
  "quantity": 20,
  "expire_time": "2026-09-12 20:00:00",
  "location": "学生街 12 号",
  "lat": "30.520",
  "lng": "120.135"
}
```

**预期**：`code: 0`，返回完整商品对象（含 `id`、`status: 1` 在售）。**记下商品 id**。

> ⚠️ `expire_time` 必须是未来时间，格式严格 `yyyy-MM-dd HH:mm:ss`；金额是字符串。

### 2.2 商品出现在列表中

`GET /api/products?page=1&size=10&keyword=奶茶`

**预期**：`code: 0`，`items` 里能找到刚发布的商品，`total >= 1`。

### 2.3 查看商品详情

`GET /api/products/{id}`

**预期**：`code: 0`，返回里有 `merchant.shop_name = "测试奶茶店"`、`image`、`is_favorite` 字段。

### 2.4 商家下架自己的商品

`PUT /api/products/{id}/offline`

**预期**：`code: 0`，返回商品 `status: 2`（已下架）。再去商品列表查，默认列表里**不再出现**该商品。

> ✅ 阶段二验证点：发布 → 列表可见 → 详情字段完整 → 下架生效。

---

## 阶段三：AI 风控拦截（核心）

每发一个违规商品，都会**写入风控日志**，稍后在阶段四核对。测试时 Authorize 里保持商家 token。

### 3.1 敏感词拦截 → 41001

`POST /api/products`，把 2.1 的请求体标题改为：

```json
{"title": "免费送 加微信领取", "original_price": "15.00", "discount_price": "5.00", "quantity": 5, "expire_time": "2026-09-12 20:00:00", "location": "学生街 12 号", "lat": "30.520", "lng": "120.135"}
```

**预期**：`code: 41001`，`message` 含「发布被风控拦截：命中敏感词」

### 3.2 虚假折扣拦截 → 41002

```json
{"title": "正常标题", "original_price": "10.00", "discount_price": "20.00", "quantity": 5, "expire_time": "2026-09-12 20:00:00", "location": "学生街 12 号", "lat": "30.520", "lng": "120.135"}
```

（折扣价高于原价）

**预期**：`code: 41002`，`message` 含「疑似虚假折扣」

### 3.3 过期商品拦截 → 41003

```json
{"title": "正常标题", "original_price": "10.00", "discount_price": "5.00", "quantity": 5, "expire_time": "2020-01-01 00:00:00", "location": "学生街 12 号", "lat": "30.520", "lng": "120.135"}
```

（有效期是过去的时间）

**预期**：`code: 41003`，`message` 含「商品已过期」

### 3.4 预警不拦截（低于 1 折）

```json
{"title": "正常标题", "original_price": "100.00", "discount_price": "5.00", "quantity": 5, "expire_time": "2026-09-12 20:00:00", "location": "学生街 12 号", "lat": "30.520", "lng": "120.135"}
```

**预期**：**`code: 0`，商品照常发布**（warn 级别只记日志不拦截）。

> ✅ 阶段三验证点：三类拦截码各自正确 + warn 级别放行。

---

## 阶段四：超管处理风控日志

重新登录 `admin`，替换 Authorize 的 token。

### 4.1 查看未处理风控日志

`GET /api/admin/risk-logs?is_resolved=0`

**预期**：`code: 0`，至少能看到阶段三产生的 4 条记录（3 条拦截 + 1 条预警），每条含 `risk_type`（1 价格 / 2 敏感词 / 3 有效期）、`risk_detail`、商品和商家信息。记下一条的 `id`。

### 4.2 标记已处理

`PUT /api/admin/risk-logs/{log_id}/resolve`

（无请求体）

**预期**：`code: 0`。再用 `is_resolved=0` 查一次，该条消失；用 `is_resolved=1` 能查到它。

### 4.3 数据看板

`GET /api/admin/statistics`

**预期**：`code: 0`，返回用户/商家/商品/订单等平台统计数据。

> ✅ 阶段四验证点：违规留痕可查、可处理、看板数据随操作变化。

## 阶段五：权限边界（负向测试）

| # | 操作 | 预期 |
|---|---|---|
| 5.1 | 用**学生** token 调 `POST /api/products` 发布商品 | HTTP 403「当前角色无权访问该接口」 |
| 5.2 | 用**商家** token 调 `GET /api/admin/statistics` | HTTP 403「仅超管可访问」 |
| 5.3 | 清空 Authorize，调 `POST /api/products` | HTTP 401（前端据此跳登录） |
| 5.4 | 商家 A（testshop01）下架商家 B（shop001）的商品 | `code: 40001`，无权限操作他人商品 |
| 5.5 | 超管禁用商家账号：`PUT /api/admin/users/{user_id}/status` body `{"status": 0}`，然后该商家再登录 | `code: 20002`，账号被禁用 |

---

## 速查表

| 错误码 | 含义 | 触发场景 |
|---|---|---|
| 20002 | 账号被禁用 | 阶段五 5.5 |
| 20003 | 商家未审核 | 阶段一 1.2 |
| 40001 | 无权限操作他人商品 | 阶段五 5.4 |
| 41001 | 敏感词拦截 | 阶段三 3.1 |
| 41002 | 定价异常拦截 | 阶段三 3.2 |
| 41003 | 有效期异常拦截 | 阶段三 3.3 |
| HTTP 401 | 未登录 / token 失效 | 阶段五 5.3 |
| HTTP 403 | 角色权限不足 | 阶段五 5.1 / 5.2 |

## 测试后清理

测完数据库里会留下「测试奶茶店」等数据。想恢复干净状态：停掉服务 → 删除 `backend/data/foodlink.db` → 重跑 `python scripts/seed_demo.py` → 重启服务。
