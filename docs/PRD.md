# 食愿 FoodLink —— 产品需求说明（PRD · 简版）

> 一句话：让校园食堂、周边商家把当日临期/余量食物低价转给学生，同时用 AI 做智能推荐和风控，减少食物浪费。

## 一、面向谁
- **学生**：想省钱、又怕浪费的在校学生（低消费吃到靠谱的一餐）。
- **商家**：有临期/余量餐食、想要低成本引流获客的校园及周边餐饮商家。
- **超管**：平台运营方，负责审核商家资质、监控平台数据和风控。

## 二、解决什么问题
- 商家临期/余量食物直接丢弃，浪费且无收益。
- 学生就餐贵、选择少，缺少「低价又有保障」的渠道。
- 平台缺少审核与风控，容易出现违规发布、无效商品、异常交易。

## 三、核心功能
- **登录注册**：学生/商家/管理员三种角色分离；商家入驻需上传营业执照、地图选点，资质需超管审核通过后才能营业。
- **学生端**：首页个性化推荐（下拉刷新、上拉加载）、商品卡片（价格/距离/折扣/过期倒计时）、收藏、下单、取货凭证码、我的订单与个人资料。
- **商家端**：发布商品（表单+地图选点+图片上传）、订单管理（查看下单学生+核销取货码）、店铺信息维护（更新后需重新审核）。
- **超管端**：商家审核（入驻/信息变更）、风控日志（拦截记录+误判恢复）、数据看板（用户/订单/帮扶/风控统计）、消费排行、**隐形帮扶**（见下方专属说明）等。

## 四、使用流程
1. **商家**：注册 → 提交资质 → 超管审核通过 → 发布临期商品 → 接收学生订单 → 线下核销取货码。
2. **学生**：注册/登录 → 浏览推荐商品 → 下单 → 凭取货码到店领取 → 评价/收藏/再次下单。
3. **超管**：审核商家 → 监控平台数据与风控日志 → 处理异常与误判恢复 → 数据看板辅助决策。

## 五、隐形帮扶（设计亮点）
管理端**每月定时**拉取全量学生消费数据跑批，识别「**消费次数很多、但消费总金额较低**」的学生（多为经济困难），自动发放优惠补助。
- **识别模型**：优先按消费次数降序，其次按总金额升序（+平均每笔金额低者更优先），命中后进入发放名单。
- **隐形化设计**：学生端**不会看到任何「帮扶 / 救济 / 贫困」字样**，通知统一措辞为「感谢您的长期忠诚使用，为您发放优惠额度」，发放记录在后台留存、支持误判调整，既做到公平又能保护学生尊严。
- 演示中该流程在管理端「优惠分配」页以本月数据一键跑批演示。

## 六、技术 / 平台 / 模型
- **前端**：Vue 3 + Vite + Vue Router + Pinia + Axios + Leaflet（地图选点），纯 Web 产品。
- **后端**：Python FastAPI + SQLAlchemy + SQLite + PyJWT。
- **开发/演示**：内置 Mock（浏览器内存模拟后端，支持 GitHub Pages 纯静态在线演示，无需服务器）。
- **AI 能力（DeepSeek）**：
  - 个性化推荐：结合用户浏览/历史与个人填报偏好，排序展示「猜你喜欢 / 为你优选」。
  - 内容风控：对发布标题/描述做语义识别（价格异常、敏感词、有效期异常），拦截并生成风控日志。
